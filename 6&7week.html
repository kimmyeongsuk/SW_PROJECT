문제: csv로 가져온 내역 카테고리 미분류

은행 명세서(CSV)에 들어 있는 정보는 날짜, 금액, 적요(가맹점명·거래 내용)뿐이다. 카테고리 정보는 없어서, 처음 만든 CSV 가져오기 기능은 모든 내역을 미분류로 저장했다.

왜 문제인가 — 이 앱의 핵심은 카테고리별 통계와 지출 패턴 분석이다. 가져온 내역이 전부 미분류면 "어디에 가장 많이 썼는지"를 볼 수 없어서, 명세서를 가져오는 의미 자체가 줄어든다.

2.1단계 — 키워드 기반 자동 분류

적요에 특정 단어가 들어 있으면 해당 카테고리로 분류하는 방식을 먼저 적용했다. 카테고리마다 연관 단어 목록을 만들어두고, 적요 문자열이 그 단어를 포함하는지 검사한다.

private static final Map<String, List<String>> CATEGORY_KEYWORDS = new LinkedHashMap<>() {{
    put("식비",   List.of("김밥", "국밥", "스타벅스", "카페", "커피", "쿠팡이츠", ...));
    put("교통",   List.of("지하철", "버스", "택시", ...));
    put("쇼핑",   List.of("쿠팡", "올리브영", "마트", ...));
    put("구독",   List.of("넷플릭스", "유튜브", "클라우드", ...));
    // 문화/여가, 의료/건강, 통신 ...
}};

키워드 분류의 동작 방식과 한계

  • 규칙 기반(사전 조회 + 선형 탐색) 방식이다. 사람이 미리 정해둔 단어 목록과 문자열을 비교할 뿐이다.
  • 목록의 순서가 곧 우선순위다. 처음 일치한 카테고리에서 바로 멈추기 때문이다.
적요(입력)일치한 단어결과
스타벅스 아메리카노스타벅스식비
넷플릭스넷플릭스구독
마트 장보기마트쇼핑
편의점(없음)미분류

3.2단계 — LLM(Claude API)으로 남은 미분류 재분류

키워드로도 걸러지지 않은 항목만 AI에게 맡겨서, 문맥으로 카테고리를 추론하게 했다. .

처리 흐름

1
버튼 클릭목록 화면의 "AI로 미분류 자동 분류" 버튼이 POST /expenses/ai-categorize를 호출한다.
2
미분류 조회카테고리가 "미분류"인 내역만 DB에서 가져온다.
3
배치 호출적요 목록을 한 번에 묶어서 API로 보낸다.
4
응답 파싱모델이 돌려준 JSON 배열을 읽어서 같은 순서의 카테고리 목록으로 변환한다.
5
저장각 내역의 카테고리를 갱신하고 한꺼번에 저장한 뒤 목록 화면으로 돌아간다.

프롬프트 설계

모델이 엉뚱한 카테고리를 만들거나 설명을 덧붙이지 못하도록, 선택지를 제한하고 출력 형식을 못박았다.

아래는 가계부 거래 내역의 적요(가맹점명/내용) 목록이다.
각 항목을 다음 카테고리 중 하나로 분류하라: 식비, 교통, 쇼핑, 구독, 문화/여가, 의료/건강, 통신, 미분류
확실하지 않으면 '미분류'로 분류하라.
반드시 JSON 배열 형식으로만 답하라. 다른 설명 문장은 절대 포함하지 마라.
예시 형식: ["식비", "교통", "미분류"]
